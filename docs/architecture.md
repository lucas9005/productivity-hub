# 🚀 Productivity Hub — System Architecture Overview

## 1. Frontend Structure

- **Organization:** Feature-based folder structure under `/src/app/` (e.g., `/tasks`, `/finance`, `/chat`, `/shared`). Each feature owns its routing, standalone components, services, and models.
- **Component Strategy:**
  - Use Angular **Standalone Components** (`standalone: true`) across all features.
  - Organize each feature as a **Lazy-loaded route** using `loadComponent` or `loadChildren`.
  - Shared visual components (like Button, Modal) reside in `/shared/components/`.
- **Routing:**
  - Central `app.routes.ts` file aggregates routes.
  - Features lazy-load their modules for better performance and scalability.
- **State Management:**
  - Prefer Angular **Signals API** for simple local and feature-level state.
  - Introduce **NgRx Store** selectively when cross-feature state becomes complex (e.g., cross-module user session sharing).
- **Future Shared Folder Usage:**
  - `/shared/` will also contain reusable Pipes, Directives, and simple Utility Services.

## 2. Backend Structure

- **Organization:** Feature-Based Modular Architecture under `/src/` (each feature in its folder).
- **Core Module:**
  - `/core/` for global singletons like ConfigService, LoggerService, Global Guards.
- **Shared Module:**
  - `/shared/` for common Pipes, DTOs, Validators, Decorators.
- **Controllers/Services:**
  - Each feature has its own Controller, Service, and DTOs, following NestJS clean architecture.
- **Testing:**
  - Unit testing with Jest for services/controllers.
  - e2e testing using SuperTest integrated with NestJS `@nestjs/testing` utilities.

## 3. Shared Principles

- **Code Style:**
  - Prettier (formatting) + ESLint (static analysis) enforced project-wide.
  - Code automatically formatted and linted on commit via Husky and lint-staged.
- **Folder Organization:**
  - Feature-first modular organization on both frontend and backend.
- **Error Handling:**
  - Frontend: Centralized Error Service + global Angular HttpInterceptor for error catching.
  - Backend: Global Exception Filters for consistent API responses.
- **Validation:**
  - Backend: DTO validation with `class-validator` and `class-transformer`.
  - Frontend: Angular Reactive Forms validation.
- **Testing:**
  - Maximum unit test coverage expected.
  - CI integration for automated test runs.

## 4. API Design

- **Architecture:** REST APIs designed following best practices.
- **Documentation:**
  - OpenAPI (Swagger) documentation auto-generated by decorators in Controllers.
- **Versioning:**
  - API routes prefixed with `/api/v1/` to allow future API versioning without breaking changes.
- **Frontend Consumption:**
  - Angular `HttpClient` services consume the REST API with strongly typed interfaces.
- **Security:**
  - API secured by Firebase Authentication token validation.

## 5. Database and Storage

- **Database:** PostgreSQL.
- **Local Development:**
  - PostgreSQL running via Docker container.
- **ORM:** Prisma ORM:
  - `prisma/schema.prisma` defines database models.
  - `prisma migrate` for managing schema evolution.

## 6. Realtime Capabilities

- **Required:** Chat App feature needs full realtime support.
- **Technology:**
  - WebSocket communication using NestJS WebSocketGateway.
  - Frontend will use `socket.io-client` or native WebSocket APIs.
- **Optional Future Realtime Modules:**
  - Task Manager (live updates).
  - Travel Planner (live itinerary and availability updates).
- **Scalability:**
  - Modular realtime support (feature by feature) without entangling backend core logic.

## 7. Authentication and Authorization

- **Authentication:**
  - Firebase Authentication integrated with frontend.
  - Secure JWT tokens issued by Firebase.
- **Backend:**
  - JWT token validation middleware/guard in NestJS backend.
- **Authorization (RBAC):**
  - Roles: User, Admin.
  - Role Guards applied to sensitive endpoints.
- **Frontend:**
  - Angular Auth Guards to protect routes based on authenticated user roles.

## 8. Monorepo Guidelines

- **Folder Layout:**
  - `/apps/frontend/` for Angular app.
  - `/apps/backend/` for NestJS app.
  - Future shared libraries inside `/libs/`.
- **Naming Conventions:**
  - Lowercase folders for apps and features.
  - Singular noun for feature folders (e.g., `tasks`, `finance`, not `task-manager`).
- **Package Manager:**
  - Bun used for development.
- **Env Management:**
  - Organized `.env` structure (`.env.dev`, `.env.prod`, `.env.local` if needed).
  - Secrets excluded via `.gitignore` and documented in `.env.example`.
